# 时知 · NowPast RAG

面向学校公告、教师课程安排和作业的校务通知原型。学生查看什么时候、在哪里、做什么，并可打开具体旧通知核查变化。教师提供标题、完整原文、公布日期和接收范围，服务整理要求并比较已有通知，无需手填要点或替代条款。

首页与通知中心隐藏算法、AI 归类和流程解释。当前资料为自编示例，相关说明收在帮助中。通知目前保存在浏览器，尚无真实学校接入、身份认证、多用户分发或服务端持久化。

**两人协作：Codex 负责 UI 设计、研究说明与独立验收，组员 AI 负责 RAG 引擎与模型服务。详见[两份执行任务](CONTRIBUTING.md)。** 每个模块的 README 都写明代码入口、第一项交付和验收条件。

本轮分支为 `codex/ai-notice-relations`，基于 PR #10 的 `54ff098`。下一轮组员按“统一校务数据和接口 → 加强原文解析与旧通知匹配 → 本地服务端保存”推进；完整顺序和交付见 [HANDOFF.md](HANDOFF.md)。PR #13 的显式校务域与本轮通知模型尚待统一。

## 跑起来

项目要求、双方分工、任务状态和自动推进的完成条件见 [要求与任务](REQUIREMENTS.md)。完整本机验收可执行 `node service/verify-delivery.mjs`，已准备模型时加 `--model`。

需要 Node.js 22 或更高版本。网页和检索直接使用 Node 与浏览器，无需安装 npm 依赖。运行 `npm test` 验证原开发回归与新通知检查。

```sh
git clone https://github.com/666Dean/NowPast-RAG.git
cd NowPast-RAG
npm start
```

打开 [本机问答工作台](http://127.0.0.1:4173/)。另开终端在仓库根目录运行 `npm run eval` 可复现评测。可选本地模型适配 Windows x64，需要 Python 3.11+，首次准备约 750 MB 缓存空间。[真实模型运行说明](generation/runtime.md)

## 三个校务验收场景

| 问法 | 应观察到的行为 |
| --- | --- |
| 教师发布教室调整 | 自动关联具体旧通知，只改变对应班级和课次的教室，保留原上课时间 |
| 教师延后作业截止 | 改变该作业的截止时间，保留原提交地点和作业内容，不影响另一份作业 |
| 查看调整公布前的日期 | 不提前看到新通知或新关联；全校公告和班级通知按范围隔离 |

## 研究边界

论文原任务是动态图链路预测。此实现借鉴 Past 与 Now 分开建模再融合的思想，独立实现条款替代图、有效快照、双通道检索和引证回答。课程通知与日期为本项目原创演示资料；论文与源码有独立的真实来源。可选 Qwen 模型负责在候选原文中选句。此版本没有训练或接入 GNP 神经网络。[研究依据与设计](research/design.md) · [论文](https://doi.org/10.1007/978-981-95-7075-1_50) · [上游仓库](https://github.com/for4ever44/GNP)

# 时知 · NowPast RAG

为复现 GNP 论文的学生和助教做的时序证据问答原型。学生拿到的可能是论文、固定提交的源码、旧手册，或一份已公布但明天才生效的补丁。时知按日期和组别给出当时该执行的要求，并让读者沿引用核查原文。

**两人协作：Codex 负责 UI 设计、研究说明与独立验收，组员 AI 负责 RAG 引擎与模型服务。详见[两份执行任务](CONTRIBUTING.md)。** 每个模块的 README 都写明代码入口、第一项交付和验收条件。

## 跑起来

需要 Node.js 22 或更高版本。网页和证据问答直接使用 Node 与浏览器，无需安装 npm 依赖。

```sh
git clone https://github.com/666Dean/NowPast-RAG.git
cd NowPast-RAG
npm start
```

打开 [本机问答工作台](http://127.0.0.1:4173/)。另开终端在仓库根目录运行 `npm run eval` 可复现评测。可选本地模型适配 Windows x64，需要 Python 3.11+，首次准备约 750 MB 缓存空间。[真实模型运行说明](generation/runtime.md)

## 三个验收问题

| 问法 | 应观察到的行为 |
| --- | --- |
| 论文和源码的融合方式有什么差异？ | 分别定位到论文 §3.2 和固定提交的 GNP.forward；可以打开各自来源 |
| 11 月 8 日，B 组用什么融合方式？ | 当时仍执行 Hadamard 乘积，同时看到 10 日才生效的源码复现补丁 |
| 11 月 12 日，B 组融合方式按哪版实现、要附哪些复现材料、去哪验收？ | 前两项有来源；地点保留两份冲突通知。切换到 18 日，能查到联合澄清及旧排班 |

## 研究边界

论文原任务是动态图链路预测。此实现借鉴 Past 与 Now 分开建模再融合的思想，独立实现条款替代图、有效快照、双通道检索和引证回答。课程通知与日期为本项目原创演示资料；论文与源码有独立的真实来源。可选 Qwen 模型负责在候选原文中选句。此版本没有训练或接入 GNP 神经网络。[研究依据与设计](research/design.md) · [论文](https://doi.org/10.1007/978-981-95-7075-1_50) · [上游仓库](https://github.com/for4ever44/GNP)

## 冻结基线

38 道当前依据集合题中，完整系统完全匹配 35 题，关闭历史通道后为 30 题。获得正确主题的最新发布日期基线完全匹配 33 题，平均集合 F1 为 96.5%，高于完整系统的 93.4%。GNP08 的双日期路由、X06/X07 的口语改写仍是开放问题。这些结果来自小型、人工组织、非盲的虚构资料测试。[逐题结果与评测口径](evaluation/REPORT.md)

此仓库是团队交接基线。Qoder 开发过程、Qoder Sites 公网部署和天池作品帖留给后续参赛阶段验收。

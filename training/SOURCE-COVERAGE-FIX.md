# 2026-11-23：引用身份与逐项完整性续跑

## 问题与修复

修改前复查的调用链：`/api/notices/analyze → analyzeNotice / analyzeDomainNotice → noticeContext → materializeNotice / validateDocument`。引用定位也影响旧通知候选检索和替代授权，因此两条模型入口都补回归，保留 answer、query/generate API、网页与原冻结金标。

1. 原上下文始终用全文第一次出现的 value 定位。两门课或两个课次使用同一教室时，后面的引用会错误继承前面的身份。现在按模型实际选择的引用定位；同一引用仍对应多个不同身份时明确拒绝，不能猜第一次。
2. 旧去重键只有主题、班级和值，不同课次相同值可能被去重。现在加入课程、具体课次或作业及字段；新版也不能用任意 activityId 字符串掩盖同一真实课次的重复条款。
3. 新版之前只核查课程、班级、课次在整篇原文出现过。现在逐条核对引用所在上下文，拒绝交换课程、班级、课次或字段。
4. 完整性原来只检查不同新值的集合。同一教室用于两天、同一截止用于两份作业，只返回其中一项仍可能被认为完整。现在保留每个明示变更的原文位置，逐项核对值及所属课程、班级、课次或作业。模型输入约束也按事项数，而非去重后的值数设置最低条款数量。
5. 原文明示“时间仍是…、平台不变”的要求不能作为新变更发布；传闻、待确认也不能被模型的肯定输出转成确定安排。带日期和教室值却缺课程/课次身份的输入保持待确认。校验只拒绝，不读取金标补齐条款。

新增测试先实际失败，再修复；失败日志和通过日志均在本地 `training/runs/raw-notices`。整份通知仍在全部校验完成后才返回成功，未修改网页发布流程。

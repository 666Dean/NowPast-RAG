# 数据与训练修订记录

1. 首版小集发现同世界两道 QA 输入逐字相同，已改为不同字段问题，并重跑全部精确重复审计。
2. 第一轮完整词元审计后，追加生效时点检查发现 future 场景中的作业没有课次日期，生效日应比较 asOf，不能比较未来课程日期。原 120k 训练标签中有 193 条引用违反此边界，试训固定 1k 中有 2 条。停止试训、保留 `runs/pilot-invalid-future` 的日志/检查点，不能把其 loss 或权重作为有效成果。修生成器的事件状态转移并强化自动校验后，重新生成所有集合，不只删除错例。
3. 旧 230 题仅用于阶段 A 诊断，不用挑选新模型。所有新测试推理必须在训练选择固定后进行；本轮 1k 是工具链试验，正式 120k 训练还缺 500 条真实人工语义审查。
4. 500 次更新后检查 loss token 数：库默认使用 target_index <= length，多监督每条样本首个 padding token，189765 比真实 assistant/EOS 188765 多 1000。保存 `pilot-invalid-padding` 的完整结果，不当作合格模型。改用项目 loss.py 的严格 target_index < length，并用已知长度 batch 验证；从官方 base 重新训练，同一数据/配置，旧原始 base 验证响应仅按输入逐字核验后复用，明确标注非新推理。
5. 冻结覆盖审查发现，原留出配置只实际区分文体/链长，没有独立的关系组合。尚未进行 test 推理，补上仅 test 中的“当前并行＋异班干扰＋未来公布澄清”组合；重新写 manifest 和 token/近重复审计。train/valid 字节保持不变，当前 1k 试训不读取该测试变更；不按已知模型测试成绩调整题目。

6. 长链覆盖检查补充日历有效性：跨到 12 月 32 日的作业值改为真正的跨月日期，重新生成 test，训练与验证压缩字节不变。新增逐原文日期日历断言。文件/词元审计都绑定数据 SHA 并防止审计过程中换文件。
